# task-001 — Запись встречи и обработка после Stop (Draft)

Статус: подготовлен для review и утверждения. Meeting cutover ещё не реализован; файловые интеграции провайдеров уже добавлены отдельно. Факты репозитория сверены на `40d9da0a` (2026-09-23).

## 1. Цель

OpenHercules сохраняет встречу локально независимо от ASR и сети. Во время встречи приложение только записывает микрофон и системный звук, показывает длительность и состояние источников. После Stop обрабатывает полную производную запись выбранным провайдером, сохраняет транскрипт со спикерами и автоматически создаёт заметки.

Одна запись может быть повторно обработана другим провайдером без изменения исходников и уничтожения предыдущих результатов. Качество провайдеров Тимур сравнивает самостоятельно после реализации.

## 2. Объём задачи

- Надёжная раздельная запись оригинальных mic/system и восстановление после перезапуска.
- Работа записи при закрытом главном окне; индикация и управление через существующее меню приложения.
- Stop с сохранением хвоста, финализацией записи и постановкой обработки в сохраняемую очередь.
- Подготовка одной общей производной аудиозаписи из двух синхронизированных источников. Полная встреча передаётся одним входом, без деления на минутные ASR-запросы.
- Подключение существующих файловых адаптеров ElevenLabs, Deepgram и Gemini с диаризацией к обработке встречи после Stop; переиспользование выбора провайдера, модели и ключа в существующих настройках.
- Сохранение исходного ответа провайдера до нормализации/публикации, переиспользование готовых парсеров текста/времени/спикеров, автоматические заметки на основе финального транскрипта.
- Повтор обработки по сохранённому аудио, сохранение предыдущих результатов и возможность их просмотреть для сравнения.
- Явные состояния записи, очереди, обработки, ограничений и ошибок в существующем интерфейсе заметки.
- Адаптация существующего meeting flow к этому порядку; исходная realtime-обработка встречи не остаётся параллельным режимом новой схемы.

## 3. За пределами задачи

- Live-транскрипт, локальный или облачный черновик, ASR/диаризация во время текущей записи.
- Второй обязательный ASR-проход, временное разбиение для обхода лимитов, overlap/dedup и склейка speaker IDs между минутными ответами.
- Автоматическая смена провайдера, выбор «лучшей модели», автоматический запуск всех трёх провайдеров.
- Собственная новая модель диаризации, кластеризация голосов между ответами, новый алгоритм source separation/подавления эха.
- Облачный backend, hosted sync, новые аккаунты, внешний брокер очереди, plugin framework, другие платформы.
- Автоматический платный benchmark, подбор моделей по качеству и новая система оценки. Это последующая ручная проверка Тимура.
- Перестройка редактора, новая библиотека встреч вместо Notes или расширение существующего чата.

## 4. Ограничения и фиксированные решения

### Продукт и совместимость

- macOS Apple Silicon; существующий Electron/TypeScript проект и Note как корневая сущность. Запись и результаты связаны с заметкой; пустые заметки продолжают работать.
- Сохранить ручные заметки, полный существующий чат и его инструменты, Dictionary/Snippets, календарь, существующие file/direct URL import, Local и поддерживаемые Self-Hosted маршруты, управление известными голосами и исправление спикеров. Задача не добавляет несуществующие возможности этим маршрутам и не обещает им встроенную диаризацию трёх новых адаптеров.
- Cutover meeting flow без compatibility shim и скрытого возврата к realtime. Используемые вне нового meeting flow провайдеры/модули не удаляются только из-за этого cutover.
- Существующие recording entry points используют новый capture/Stop lifecycle; существующая автоматическая остановка проходит ту же безопасную финализацию, что и Stop.
- MIT attribution импортированного OpenWhispr сохраняется. Исходный профиль OpenWhispr не используется для проверок.

### Запись и её жизненный цикл

- Исходные источники сохраняются раздельно до обработки, без удаления/перезаписи при retry. Размер/кодек файлов хранения — решение Plan, не размер запроса ASR.
- Capture стартует без сети, ключа провайдера и загруженной ASR-модели. Ошибка ASR не мешает записывать.
- Обработка предыдущей встречи не блокирует начало и сохранение новой. Уже отправленный HTTP-запрос может завершиться с сохранением ответа; новые ASR-запросы и тяжёлая локальная подготовка ожидают окончания текущего capture. Обработчик уступает ресурсы записи без повторной отправки завершённого запроса.
- Оба источника непрерывно дописываются в восстанавливаемые файлы, без накопления десятков секунд аудио в памяти. При аварии процесса и исправном хранилище проверяемый предел потери уже полученного capture-процессом хвоста — не более 1 секунды на дорожку. Измерение охватывает буферы, межпроцессную передачу, очередь записи и кодировщик; одного периодического flush недостаточно для доказательства. При обычном Stop/выходе сохраняется весь полученный хвост.
- Незакрытые файлы восстанавливаются по фактически читаемым кадрам. Сбой питания/ОС и отказ накопителя не входят в секундную гарантию; ошибки или невосстанавливаемые интервалы обозначаются явно. Plan выбирает формат и механизм фиксации, реализация подтверждает предел аварийными испытаниями, а не комментариями в коде.
- Контролировать отставание записи. При исчерпании допустимого буфера/нарушении возможности сохранять звук, disk-full или ошибке write/flush остановить захват с явной ошибкой, сохранить доступное аудио и доступные метаданные неполноты. Не показывать продолжающуюся нормальную запись. Если диск не принимает даже метаданные ошибки, незакрытая сессия при restart должна обнаруживаться как неполная по ранее сохранённому состоянию.
- Недоступность system source не превращается в незаметную mic-only встречу. Отсутствие/обрыв источника и известные интервалы потерь сохраняются и видны; тишина сама по себе не доказывает отказ источника.
- Закрытие главного окна не останавливает запись. При аварии renderer сохраняются уже зафиксированные аудиоданные, а прерванный захват отмечается неполным. Продолжение микрофонного захвата через renderer crash не является требованием.
- Полный выход во время записи требует подтверждения. Отмена сохраняет работающую запись. Подтверждение останавливает и сохраняет её до завершения процесса; задание обработки продолжается при следующем запуске. Повторный Stop/выход не создаёт дублирующие записи и задания.
- После аварии приложение восстанавливает доступное аудио, отмечает запись незавершённой/неполной и автоматически ставит восстановленную запись в обработку. Лимиты API, отсутствие ключа или повреждённые входные данные остаются явными препятствиями отправке; исходники сохраняются.

### Вход провайдера и спикеры

- Согласован **один общий производный файл** после Stop, а не независимое ASR каждой дорожки. Микширование сохраняет общую шкалу времени; исходники остаются раздельными. Нельзя соединять дорожки последовательно или сжимать пропуски времени.
- Это обычный общий аудиовход с диаризацией, а не multichannel-режим «один канал = один человек». Спикеров определяет провайдер по полной встрече.
- Допустимый trade-off: при одновременной речи точность смешанного входа может снизиться. Тимур проверяет качество на своих записях; идеальное разделение перебивающих людей не является обещанием задачи.
- Повтор эха в mic/system — известный риск смешивания. Существующее подавление эха можно переиспользовать только на производной обработке при корректной синхронизации; исходники сохраняются до такой обработки. Новые ML-модели/эвристики не вводятся для гипотетического улучшения качества.
- Speaker A/B не означает имя человека. Сохранить возможность исправлять имена и существующие инструменты узнавания голосов; календарь и источник mic не являются доказательством личности. Отсутствующее/неопределённое имя не выдумывается.
- Speaker IDs принадлежат конкретному результату. Новый запуск не наследует исправления по совпадению числовых IDs; предыдущий результат и его исправления остаются доступны.

### Провайдеры и результаты

- ElevenLabs, Deepgram и Gemini входят сразу через уже реализованные файловые адаптеры; предварительный benchmark или выбор одного победителя не требуются. Переиспользовать существующие маршрутизацию, registry, credentials, транспорт и парсеры, расширяя их под сохраняемую обработку встречи без второй реализации тех же API.
- Каждое задание хранит выбранные provider/model/config и обрабатывает запись только этим провайдером. Секреты не копируются в аудиоманифесты, результаты и журналы; использовать существующий механизм credentials.
- Перед отправкой проверяются применимые лимиты полного входа и возможности API. При превышении показать причину и предложить выбрать другого провайдера. Не отправлять обрезанное аудио, не отключать молча диаризацию и не разделять запись автоматически.
- Исходный JSON-ответ сохраняется локально до нормализации и публикации, включая полезный ответ с неполными метаданными. Нормализацию можно повторить из сохранённого ответа без нового платного ASR; существующий контракт `text / segments / diarized` служит основой результата, а provider-specific данные остаются внутри этапа обработки. Полный результат содержит текст, временные метки и доступные speaker labels. Не объявлять успешную полную диаризацию, если запрошенные метаданные отсутствуют; сохранить полезный ответ и показать ограничение/ошибку этапа.
- Очередь и результаты переживают перезапуск; SQLite уже используется приложением. Не нужен отдельный сервис или брокер.
- Сохранённый результат используется повторно при ошибке последующих этапов. Не обещать exactly-once оплаты: при аварии между ответом сервера и локальным сохранением исход запроса может быть неизвестен. Исключить дубли локальных результатов; применимые механизмы получения результата/idempotency определяются контрактом API.
- Финальный транскрипт сохраняется до автоматических заметок. Ошибка summary оставляет аудио/транскрипт доступными и позволяет повторить только summary. Ручной текст заметки не теряется.

### Хранение, удаление и доступ к аудио

- По умолчанию аудио хранится **7 дней** с окончания capture. Срок задаётся существующей настройкой: неотрицательное число дней, `0` означает хранить бессрочно. 7 дней — default только при отсутствии сохранённого значения; существующие пользовательские значения сохраняются без миграции. Настройка применяется к существующим и новым записям. При уменьшении срока интерфейс предупреждает, что уже просроченное аудио будет удалено. Для аварийной записи отсчёт идёт от последнего восстановленного capture timestamp, а не заново от запуска приложения.
- Автоочистка удаляет raw-дорожки и все локальные производные/временные аудиокопии записи. Транскрипты, raw JSON-ответы без аудио, speaker corrections, сгенерированные и ручные заметки остаются до удаления заметки. UI показывает отсутствие аудио; playback/export аудио и повторное ASR недоступны, работа с текстом и повтор summary доступны.
- Просроченное аудио удаляется при ближайшей очистке работающего приложения, в том числе после запуска. Приложение не обещает очистку пока оно выключено. Активный capture не истекает. Ожидающее/ошибочное задание не продлевает срок хранения бесконечно: истечение отменяет требующее аудио задание и обозначает причину. Активный доступ к удаляемому аудио прекращается; поздний ответ не создаёт аудиофайлы заново. Не обещать удаление уже принятого провайдером файла или отмену его тарификации.
- Использовать существующие настройки хранения/очистки там, где они соответствуют новым записям, без второго конкурирующего sweeper. При отсутствии настройки используется новый default 7 дней вместо 30; ранее сохранённое значение, включая 30 или 0, не перезаписывается. Existing transcript/history retention не должен удалять финальные результаты новых Notes как старую dictation history.
- Удаление заметки явно удаляет все её локальные записи, производные файлы, ответы, результаты/версии, speaker mappings и задания. Общие профили голосов, используемые другими заметками, не удаляются. Поздние callbacks не воссоздают удалённую заметку. Удаление активной записи требует остановки и подтверждения удаления; оно не запускает её ASR.
- Существующее действие удаления всего аудио охватывает и новые записи/копии; текст остаётся. Для активной записи сначала требуется остановка с подтверждением. Не добавлять отдельные UI удаления каждого промежуточного артефакта: они следуют родительской заметке или сроку аудио.
- Cleanup идемпотентен, незавершённое удаление файлов после сбоя продолжается при запуске; ошибка удаления видна, операция не выдаётся за завершённую, пока относящиеся к ней файлы остаются. Экспортированные пользователем копии вне управляемого хранилища приложение не удаляет.
- Пока аудио существует, пользователь может прослушать общую запись с переходом по метке времени и экспортировать общую копию либо исходные mic/system без изменения оригиналов. Экспорт завершается только после успешной записи читаемого файла. Существующие текстовые экспорты Notes/транскрипта сохраняются; новый формат экспорта не требуется.

## 5. Пользовательский сценарий

1. Пользователь выбирает провайдера в существующих настройках и начинает запись из существующего интерфейса заметки. Отсутствие настройки облака не блокирует захват.
2. Во время встречи доступны ручные заметки, длительность и состояние mic/system. Автоматического текста нет. Закрытие окна оставляет запись активной и управляемой через меню.
3. Stop завершает захват и сохраняет запись. UI различает «Запись сохранена», «В очереди», «Обработка», «Готово» и конкретную причину ошибки/ограничения.
4. Когда вход готов и provider доступен, приложение отправляет общий файл на ASR с диаризацией. Без сети работа сохраняется до восстановления доступа; при неверном ключе или лимите требуется исправление/выбор пользователя.
5. Пользователь получает финальный транскрипт со временем и спикерами, затем итоговые заметки. Отметка о неполной записи сохраняется независимо от успешности ASR.
6. Пользователь может прослушать/экспортировать сохранённое аудио, исправить спикеров и повторить обработку другим провайдером. Предыдущий результат не уничтожается и доступен для сравнения; отдельный сравнительный dashboard не нужен.
7. После аварии приложение автоматически восстанавливает и обрабатывает сохранившуюся запись, явно показывая её состояние. После подтверждённого выхода во время записи обработка возобновляется при следующем запуске; уже истёкший срок хранения сначала обрабатывается как удаление аудио, без отправки ASR.
8. В настройках пользователь видит свой сохранённый срок либо default 7 дней и может изменить его, включая бессрочное хранение. По истечении аудио удаляется, текст остаётся. Удаление всей заметки удаляет её связанные локальные данные и задания.

## 6. Ожидания от проверок

Использовать существующие Node tests (`node --import tsx --test --test-concurrency=1`) и изолированный Electron smoke. Tests/build/install выполняются последовательно с координацией между агентами.

- Unit: границы finalization и идемпотентный Stop, преобразование ответов трёх API, ограничения входа, позиции в общей шкале, состояния отсутствующего источника.
- Integration на временных файлах/БД и подменённых provider responses: запись → Stop → job → ответ → транскрипт → summary; offline/restart, восстановление неполного захвата, сохранённый ответ после сбоя публикации, независимый retry summary, сохранение старых результатов/ручных заметок.
- Integration хранения и lifecycle: истечение 7 дней/изменённого срока, сохранение прежних значений и отсутствие очистки при 0, cleanup после restart, удаление заметки/всего аудио при pending/in-flight job, игнорирование позднего ответа, повторное удаление, сохранение текста при audio-only cleanup и общих голосовых профилей при note-delete. Проверить, что старый retention не удаляет Notes-результаты и не переопределяет новый default.
- Integration capture: новая запись при pending/active старом задании; disk-full/write-failure, контролируемое отставание, recovery незакрытого файла, секундный предел в тестовой цепочке захвата/записи. Playback/export: читаемый файл, оба оригинальных источника, сохранение длительности/позиций, ошибка назначения и недоступность после audio deletion.
- Переиспользовать существующие контрактные fixtures трёх адаптеров и проверки маршрутизации/retry; дополнять их под новые границы сохранения ответа, нормализации и восстановления. Сохранить coverage запроса, текст/time/speaker mapping, авторизации/лимитов/временного отказа и ответа без обязательных метаданных, включая временные метки ElevenLabs при выключенной диаризации. Без платных вызовов в автоматических тестах.
- Изолированный macOS arm64 smoke: реальный mic/system, закрытие окна, отмена/подтверждение выхода, Stop посреди речи, смена устройства, симуляция отказа записи и recovery после принудительного завершения процесса в разные моменты. На контрольном аудио подтвердить потерю хвоста не более 1 секунды каждой дорожки при исправном диске; проверить путь к секунде из транскрипта и воспроизводимость экспорта. При отсутствии доступа к реальным устройствам отметить непроверенное поведение; не заменять доказательство mocked тестом.

## 8. Критерии приёмки

1. Встреча записывается в два сохраняемых источника без ASR/диаризации/черновика и без зависимости от сети или готовности модели. Пропавшая дорожка не маскируется полной записью.
2. Stop сохраняет весь полученный хвост и завершает метаданные до запуска обработки. Повторный Stop не дублирует работу.
3. Главное окно можно закрыть и открыть без прекращения записи. Полный выход во время записи требует подтверждения; подтверждённый выход сохраняет запись, отменённый продолжает её.
4. После перезапуска доступные данные незавершённой записи восстанавливаются, её неполнота видна, обработка ставится в очередь автоматически. Завершённые файлы и артефакты не теряются из-за retry.
5. После Stop создаётся синхронизированная общая копия; исходники сохраняются. Нет автоматических минутных запросов и обязательного повторного ASR.
6. Все три выбранных провайдера доступны для file ASR с диаризацией в рамках своих контрактов. Неподдерживаемый вход блокируется явно с возможностью выбора другого провайдера; нет скрытого переключения/обрезания.
7. Текст, время и спикеры нормализованы из сохранённого ответа; отсутствие запрошенной диаризации не выдаётся за успешную полную обработку. Имена не выводятся из календаря или номера канала без подтверждения.
8. Очередь, выбранная конфигурация и результаты переживают перезапуск. Локальная публикация не дублирует сегменты. Ошибка заметок не запускает ASR заново.
9. Финальный транскрипт предшествует автоматическим заметкам; ручные заметки и прошлые результаты сохраняются. Новая обработка другим провайдером доступна из того же исходника и оставляет предыдущую версию доступной.
10. Существующие Notes, чат, импорт, Local/поддерживаемые Self-Hosted и speaker management сохраняются в пределах их существующих возможностей. Meeting cutover не оставляет параллельный realtime-preview путь.
11. При аварии процесса на исправном хранилище восстанавливается полученное аудио с потерей хвоста не более 1 секунды на дорожку; обычный Stop сохраняет весь хвост. Ошибка записи на диск/отставание прекращает capture с явным неполным состоянием. Закрытые файлы остаются читаемыми.
12. Аудио автоматически удаляется через настраиваемый срок, по умолчанию 7 дней, при работающем приложении/следующем запуске. Raw и производные аудиокопии удалены, текст сохранён; недоступность повторного ASR/playback/export явно показана.
13. Удаление заметки очищает связанные локальные файлы/результаты/задания без удаления общих голосовых профилей. Повтор, restart и поздний ответ не воскрешают удалённые данные. Ошибка удаления не скрывается.
14. Новая запись начинается и сохраняется при pending/in-flight обработке старой. Результат уже отправленного запроса может сохраниться, новые тяжёлые этапы не конкурируют с capture.
15. Пока аудио хранится, воспроизведение/переход по времени и экспорт общей копии/оригинальных дорожек работают; экспорт не изменяет исходник, ошибки записи экспортного файла видны.
16. Выполнены применимые проверки из раздела 6; ограничения реального smoke и непроведённые платные/качественные эксперименты обозначены явно.

## 9. Решения, принятые в Brainstorm

| Развилка | Решение |
| --- | --- |
| Текст во время встречи | Полностью отказались, включая локальный черновик |
| Когда запускать ASR | После Stop и сохранения полной записи |
| Провайдеры | Сразу ElevenLabs, Deepgram, Gemini; Тимур тестирует качество позже |
| Превышение лимита | Показать ограничение, предложить другого провайдера; не делить автоматически |
| Закрытие окна | Запись продолжается в фоне, управление через меню |
| Полный выход | Подтверждение → сохранить → обработать при следующем запуске |
| Восстановленная после аварии запись | Обрабатывать автоматически, сохраняя отметку о неполноте |
| Вход ASR | Одна общая производная запись; raw mic/system сохраняются отдельно |
| Хранение аудио | По умолчанию 7 дней; срок настраивается, текст остаётся |
| Crash recovery | Непрерывная запись, восстановление незакрытого файла, цель ≤1 секунды потери при process crash, подтверждаемая испытанием |
| Ошибка диска | Остановить capture, показать ошибку и сохранить доступные данные |
